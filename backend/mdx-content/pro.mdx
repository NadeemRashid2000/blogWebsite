# Process Management in Operating Systems

## Introduction

Our computer is like a battlefield where multiple programs are constantly fighting for CPU time. Without a proper management system, everything would slow down, freeze, or even crash. Whether you're browsing the web, running apps, or handling background tasks, something needs to decide which process gets priority and how system resources are shared.

This is where the Operating System (OS) comes in—it acts as the ultimate manager, ensuring that every process gets a fair share of CPU time, avoiding conflicts, and keeping the system running smoothly.

But what exactly is a **process**? Simply put, **a process is a running instance of a program.** Each process has its own memory, registers, and execution state, allowing multiple processes to run simultaneously without interfering with each other.

## 1. What a Process Is and Its Lifecycle

A process is an instance of a program in execution. While a program is just a set of stored instructions (such as a `.exe` file or a script), it becomes a process when it is loaded into memory and starts running.

### Process States:

1. **New (Created):** A process starts in the New state when it is created. The OS assigns memory and resources before execution.
2. **Ready:** The process is waiting for CPU allocation.
3. **Running:** The process is actively executing instructions.
4. **Waiting (Blocked):** The process is paused, waiting for an external resource (e.g., user input, disk I/O).
5. **Terminated (Exit):** The process has finished execution and is removed from memory.

## 2. How the OS Tracks Processes Using the Process Control Block

The **Process Control Block (PCB)** stores key information about each process, ensuring efficient tracking and scheduling.

### Key Components of the PCB:

- **Process ID (PID)**: A unique identifier for each process.
- **Process State**: The current status (New, Ready, Running, Waiting, Terminated).
- **Program Counter**: Stores the address of the next instruction.
- **CPU Registers**: Holds process-specific data and execution information.
- **Memory Information**: Contains details about allocated memory.
- **I/O Information**: Tracks input/output device interactions.
- **Priority**: Determines CPU scheduling order.

## 3. How Process Scheduling Ensures Efficiency

To efficiently allocate CPU time, the OS follows three scheduling levels:

- **Long-Term Scheduling**: Controls which processes enter the system.
- **Short-Term Scheduling**: Decides which process gets CPU time next.
- **Medium-Term Scheduling**: Swaps processes in and out of memory for efficiency.

## 4. Context Switching: The Backbone of Multitasking

Context switching allows the OS to switch between processes efficiently.

### How Context Switching Works:

1. **Interrupt/System Call:** A process is interrupted.
2. **Save Process State:** The OS stores the current process’s execution state in its PCB.
3. **Load Next Process:** The OS retrieves another process's saved state.
4. **Resume Execution:** The new process starts execution.
5. **Repeat:** When needed, the OS switches back to the original process.

## 5. Process Creation & Termination

Processes in UNIX-based systems are created using the `fork()` system call.

```c
#include <stdio.h>
#include <unistd.h>

int main() {
    int pid = fork();
    if (pid > 0) {
        printf("Parent Process: PID = %d, Child PID = %d\n", getpid(), pid);
    } else if (pid == 0) {
        printf("Child Process: PID = %d, Parent PID = %d\n", getpid(), getppid());
    } else {
        printf("Fork failed!\n");
    }
    return 0;
}
```

### Process Termination Methods:

1. **Normal Termination:** Process completes execution successfully.
2. **Abnormal Termination:** Process crashes due to an error.
3. **Killed by Another Process:** The `kill` command is used to forcefully terminate a process.

Example:

```sh
ps aux | grep process_name
kill -9 PID
```

## 6. Real-World Use Cases & Examples

### **Google Chrome: Multi-Process Architecture**

- Each tab runs as a separate process.
- Plugins and extensions have their own processes.
- Processes run in a sandbox for security.

![Chrome Multi-Tab](https://dev-to-uploads.s3.amazonaws.com/uploads/articles/vjuqysg76cr9td4ai90b.png)

### **Linux System Processes with `systemd`**

- `systemd`: Manages system services and processes.
- `cron`: Handles scheduled tasks.
- `sshd`: Manages remote SSH connections.

To view running processes:

```sh
ps aux | head -10
```

For real-time monitoring:

```sh
top
```
